# CLAUDE.md

Guidance for Claude Code (and other coding assistants) working in this repository. Human
contributors: the same rules are in [CONTRIBUTING.md](CONTRIBUTING.md).

## Project

**FamilyFood** is a native iOS app that helps families plan a week of dinners with attention
to diet, allergies, variety and what the children already eat at kindergarten, and turns the
plan into a shopping list. See [README.md](README.md) for what works today and what is not built.

## Constraints that shape every change

- **On-device only.** No backend, no accounts, no analytics. The only network calls are the
  user-initiated imports described in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- **No bundled secrets.** The Anthropic API key is the user's own, entered in Settings. Never
  add a key, token or fallback credential to the code, a resource or a test.
- **No third-party dependencies** without discussing it in an issue first.
- **Content must be redistributable.** Recipes, images and artwork committed here have to be
  original or openly licensed. Local content you cannot redistribute belongs in the gitignored
  `LocalOverlay/` folder.
- **UI strings are German.** There is no localisation layer yet; do not mix languages in the UI.

## Tech stack and layout

Swift, SwiftUI, SwiftData. MVVM, organised by feature:

```
FamilyFood/
├── App/                 entry point, root view, tab container
├── Features/<Feature>/  Views/ and ViewModels/ per feature
├── Models/              data structures (RecipeModel, WeeklyPlan, KitaMealPlan, UserSettings, WeekKey)
├── Services/            business logic (suggestion engine, stores, import and parsing)
├── DesignSystem/        AppTheme tokens and shared components
├── Utilities/
└── Resources/           fonts, asset catalog, sample recipes
ShareExtension/          share target; hands payloads to the app through the App Group
FamilyFoodTests/         unit tests
Config/                  signing configuration (xcconfig)
```

- Logic belongs in `Services/` and `Models/`; view models hold state and presentation logic;
  views render. Do not put business logic in views.
- Every colour, font, spacing and radius comes from `AppTheme`. If a value is not a token, add
  or change the token — see [docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md).

## Xcode project

The `.xcodeproj` is **generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)** from
`project.yml` and is not committed.

- Never edit `FamilyFood.xcodeproj` by hand and never commit it.
- New files: put them under a path already covered by a target's `sources:` and regenerate.
- New targets, source paths or build settings: change `project.yml`, then `xcodegen generate`.
- Info.plist files are generated from the `info:` blocks in `project.yml`.
- Signing values (team, bundle id prefix, App Group) come from `Config/Signing.xcconfig`, with
  optional personal overrides in the gitignored `Config/Signing.local.xcconfig`. Never put a
  team id or a personal bundle id into `project.yml` or a committed file.

## Build and test

```sh
scripts/test.sh                                              # regenerate the project + run all tests
scripts/test.sh -only-testing:FamilyFoodTests/WeekKeyTests   # extra xcodebuild args pass through
FF_DESTINATION='platform=iOS Simulator,name=iPhone 17' scripts/test.sh
```

- Write the failing test first for any change to a view model, service or model, watch it
  fail, then make it pass.
- Tests must not use the network, a real API key, or the real app container — inject temporary
  directories and test doubles, as the existing tests do.
- Report the actual result of `scripts/test.sh` (pass and fail counts) before calling work done.

## Workflow

- Branch from `main`; one focused change per pull request.
- Commit messages follow `type(scope): summary` — `feat`, `fix`, `refactor`, `chore`, `docs`,
  `build`, `test`.
- Open a pull request; CI runs `scripts/test.sh`. Describe what changed and how it was tested,
  with screenshots for UI changes.
- Never commit build products (`.ipa`, `.app`, `.xcarchive`), API keys or personal data. Enable
  the commit guard once per clone: `git config core.hooksPath scripts/hooks`.
